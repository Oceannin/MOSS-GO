# ComfyUI API graphs

These examples are generated by the same `build_workflow` function used by the
studio. They make model loading, conditioning, sampling, decode and compositing
inspectable without starting the application.

| File | Use |
| --- | --- |
| `moss-create-api.json` | MOSS SFT creation with its tested plugin loader family |
| `flux-create-api.json` | Four-step FLUX.2 Klein 4B creation |
| `flux-reference-api.json` | A new station scene from an original character reference |
| `flux-masked-refine-api.json` | Full-frame FLUX edit, feathered mask and composite back onto the source |

Use the pinned Balanced files in [model setup](../docs/MODELS.md). Reference and
refinement require `mira.png`, bundled in `moss_go/web/examples`, uploaded to
ComfyUI's input storage. Refinement also needs `mira-edit-mask.png` from this
directory. Replace each `LoadImage` / `LoadImageMask` filename with the actual name
returned by your upload; ComfyUI can rename a file to avoid a collision.

These are API-format graphs for ComfyUI's `/prompt` endpoint. The studio handles
uploading and queue ownership for normal use. **Recipe** export includes the
actual execution graph, seed, models, input and mask for the selected take.
The application can additionally crop a tight edit with context and restore its
coordinates; this small standalone example demonstrates the full-frame mask path.

Regenerate the examples from source:

```sh
python scripts/export_workflows.py
```

Exporting the JSON does not run a model. The bundled mask is an illustrative
selection, not a guarantee that every detail inside the mask will remain unchanged.
