# Отправка MOSS GO на Open Source Higgsfield

Инструкция для конкурсной preview-версии **0.1.0-rc.1**. Основной сценарий проверен
на Windows / RTX 4070 Ti SUPER 16 GB. Дополнительные проверки перенесены в
[ручной чек-лист](MANUAL_CHECK_RU.md); непроверенные конфигурации перечислены в
[release notes](RELEASE_NOTES.md). Заявку и соглашения формы отправляет автор.

## 1. Проверить актуальное окно подачи

Откройте [условия конкурса](https://comfy.org/open-source-higgsfield/) и
[форму подачи](https://form.typeform.com/to/V1dSQrkS). На момент исследования онлайн-дедлайн:
**30 октября 2026, 09:00 PT — 21:00 Екатеринбурга**. Окончание полной разработки может
оказаться позже. Подача после закрытия требует подтверждённого организаторами окна;
эта инструкция не подтверждает поздний допуск.

Если регистрация ещё не выполнена, используйте
[форму регистрации](https://form.typeform.com/to/Ayn9Cwfj).

## 2. Подготовить ссылки и проверить их без авторизации

Понадобятся:

- Публичный GitHub-репозиторий с исходниками, workflow, открытой лицензией и установкой.
- Ссылка на видео, которое показывает приложение и его устройство менее чем за две минуты.
- Ссылка на социальный пост с видео и `#OpenSourceHiggsfield`.
- Необязательная ссылка на действительно работающий генератор для жюри.

Репозиторий — [Oceannin/MOSS-GO](https://github.com/Oceannin/MOSS-GO).
Перед подачей проверьте доступность Release, README и папки `workflows`.

Откройте ссылки в отдельной сессии браузера без GitHub/YouTube-авторизации. Жюри должно
иметь доступ к исходникам и просмотру видео. Локальный `127.0.0.1` не подходит в качестве
live-ссылки для жюри. Записанное или статическое демо не является работающим генератором.

## 3. Подготовить демо и социальную публикацию

Целевая длительность — **1:45–1:55**. Начните с референса рядом с готовыми сценами.
Далее покажите настоящий запуск, выбор варианта, локальную маску, сохранение и второй
дизайн персонажа. В конце кратко объясните ComfyUI-граф, свои компоненты и условия запуска.
Ускоренное ожидание обозначьте подписью. Интерфейс при первом открытии должен быть английским.

Используйте собственных оригинальных персонажей и разрешённые изображения. Проверьте
SFW-содержимое всех кадров, заголовков, обложки и репозитория. Не добавляйте музыку,
права на которую неизвестны. Английские подписи должны позволять понять демо без звука.

Черновик социального текста, который следует сверить с финальными возможностями:

> MOSS GO is a local image studio built on ComfyUI. Bring an original character,
> create scenes, refine a selected area, and keep the workflow and recipe.
> Open weights, inspectable steps, your hardware.
>
> Demo: [вставить подтверждённую ссылку]
> Source and setup: [вставить публичный репозиторий]
> #OpenSourceHiggsfield

Опубликуйте пост на одной из площадок из формы — например, X или Reddit — и скопируйте
ссылку именно на публикацию, а не на профиль. Публикация поста этой инструкцией не выполняется.

## 4. Заполнить форму

Личные поля заполните самостоятельно: имя для авторства, Comfy email, страна и нужные
социальные аккаунты. Название проекта: **MOSS GO**.

Описание до 100 символов:

> Local image studio: character scenes, masked edits and reproducible ComfyUI recipes.

Заполняйте поля по фактически выпущенной версии:

| Поле | Что указать |
|---|---|
| GitHub repo URL | Публичный репозиторий финальной версии |
| Demo video URL | Видео менее двух минут, доступное по ссылке |
| Live link | Только работающий удалённый генератор; поле необязательное |
| Social post | Публикация с видео и конкурсным хештегом |
| Parts of ComfyUI used | Comfy API; другие пункты — только если они действительно используются |
| Generative models used | Все модели финального приложения и демо, с указанием необязательного помощника |
| Other tools or techniques | Собственная подготовка графов, управление заданиями, маска, переносимые рецепты; сторонние адаптации с авторством |

Не отмечайте SDK, Router, Cloud Agent или MCP только потому, что приложение написано
с помощью ИИ. Эти пункты относятся к использованным механизмам ComfyUI.

## 5. Выбрать категории

- Для **Open Weights Only** используйте проверенный default pack: FLUX.2 Klein
  4B FP8, Qwen3 4B encoder и FLUX.2 VAE; их источники и Apache-2.0 указаны в
  [MODELS.md](MODELS.md). Не включайте экспериментальный CharRef или сторонние
  непроверенные LoRA в демонстрацию и заявление о полностью открытых весах.
- **Best Overall** рассматривается автоматически.
- **Most Innovative** выбирайте с конкретным объяснением собственного технического вклада.
- Для **Most Viral** демонстрируйте понятный и пригодный для повторения сценарий.
- Бонус **Built with FLUX 3** не относится к FLUX.2 Klein. LTX и MiniMax H3 требуют
  соответствующую основную видеомодель, а не вспомогательный пример.

На вопрос о полностью открытом стеке отвечайте по результату аудита, а не по наличию
нашей лицензии Apache-2.0. Проверяются также энкодер, VAE, LoRA и остальные зависимости.

## 6. Проверить соглашения и отправить

Перед отправкой самостоятельно прочитайте соглашения формы, включая условия показа
работы с авторством. Подтверждения о лицензии, SFW, правах и единственной заявке должны
соответствовать действительности. По условиям допускается одна заявка на человека.

После Submit сохраните подтверждение, время отправки, ссылки и commit/tag поставки.
Возможность изменения уже отправленного ответа заранее не подтверждена. Сохранённый
черновик или регистрация сами по себе не означают, что конкурсная работа отправлена.

## 7. Что проверить после подачи

- Ссылки продолжают открываться без авторизации.
- Приложение устанавливается по опубликованной инструкции.
- Benchmark-таблица не называет непроверенные GPU проверенными.
- Если предоставлена live-ссылка, она доступна и имеет очередь/лимиты. В форме указаны
  ориентировочно 5–10 запусков для проверки жюри.
- На релизе явно указаны известные ограничения; демо не обещает отсутствующие функции.
